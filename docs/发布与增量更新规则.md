# VisionWorkbench 发布与增量更新规则

## 发布物

每个版本默认生成两类发布物：

- 全量安装包：用于首次安装、重大版本升级、安装损坏恢复或无法匹配增量包时使用。
- 增量更新包：以旧版本为基线，仅包含发生变化的程序文件。

普通增量更新包不覆盖以下内容：

- 客户数据目录、数据库、配置、日志、录制视频和检测结果；
- `runtime/python`、`runtime/mvs` 等运行时；
- `plugins/*/models` 下的模型文件。

## 组件更新

模型和运行时不随每个普通版本重复传输：

- 模型变化时生成独立模型组件包，按 SHA-256 只更新缺少或发生变化的模型；
- Python、CUDA 或海康 MVS Runtime 变化时生成独立运行时组件包；
- 组件包安装后必须重新执行环境自检。

## 客户端更新流程

```text
检查当前版本和更新基线
→ 停止 VisionWorkbench
→ 备份程序目录和必要配置
→ 校验更新包签名、大小和 SHA-256
→ 替换增量文件并删除已废弃文件
→ 执行数据库迁移
→ 执行环境自检
→ 成功后完成更新；失败则回滚
```

增量更新不能覆盖客户数据。版本基线不匹配、文件校验失败或更新过程中断时，使用全量安装包恢复。

## 构建约定

先构建当前版本的 `artifacts/installer-staging`，再使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-incremental-update.ps1 `
  -BaseReleaseDirectory <旧版本安装目录或旧版本 staging 目录> `
  -CurrentReleaseDirectory .\artifacts\installer-staging `
  -OutputDirectory 'E:\AI执行软件安装包'
```

脚本会生成带基线版本、目标版本、变更文件、删除文件和 SHA-256 的更新清单，并输出增量 ZIP 包。全量安装包仍使用 `build-installer.ps1` 生成并保留。

在客户程序已关闭且确认基线版本匹配后，可使用以下脚本应用普通增量包。脚本会校验包内文件哈希，更新失败时恢复备份：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\apply-incremental-update.ps1 `
  -PackagePath <增量 ZIP 路径> `
  -InstallDirectory <客户安装目录>
```

组件更新示例：

```powershell
# 只生成模型差分包
powershell -ExecutionPolicy Bypass -File .\scripts\build-incremental-update.ps1 `
  -BaseReleaseDirectory <旧版本安装目录> `
  -CurrentReleaseDirectory .\artifacts\installer-staging `
  -OutputDirectory 'E:\AI执行软件安装包' `
  -Component models

# 只生成 Python/CUDA/MVS 运行时差分包
powershell -ExecutionPolicy Bypass -File .\scripts\build-incremental-update.ps1 `
  -BaseReleaseDirectory <旧版本安装目录> `
  -CurrentReleaseDirectory .\artifacts\installer-staging `
  -OutputDirectory 'E:\AI执行软件安装包' `
  -Component runtime
```

## 发布检查

每次发布必须记录：

- 全量安装包路径、大小和 SHA-256；
- 增量包路径、大小和 SHA-256；
- Git 提交号和 Gitee 推送状态；
- 全新目录安装测试、增量更新测试、环境自检和回滚测试结果。
