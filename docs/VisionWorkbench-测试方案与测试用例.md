# VisionWorkbench 测试方案与测试用例

> 文档版本：1.0  
> 配套设计：`VisionWorkbench-总体方案设计.md`  
> 适用范围：Windows AI 视觉工作台 MVP 及后续扩展版本

## 1. 测试目标

本测试方案用于验证 VisionWorkbench 在功能、算法契约、设备兼容、计数准确性、性能、稳定性、故障恢复、数据完整性和安装交付方面是否满足设计要求。

重点验证：

1. WPF 主程序在算法、相机或外部组件故障时保持可用；
2. Python、ONNX 和后续 C++ Worker 能按统一协议接入；
3. 静态计数、动态去重计数和流水线计数符合定义；
4. CPU 模式能够完成基础任务，GPU 模式能够正确加速和回退；
5. 实时预览、算法推理、记录写入相互解耦；
6. 现场人员使用视觉配方即可运行，无需调整专家参数；
7. 检测结果、模型版本、计数事件和人工修正可以追溯；
8. 一个项目可管理多个独立工位，所有结果能被外部设备准确识别来源工位；
9. 软件可以连续稳定运行并从常见故障中恢复。

## 3. 测试原则

### 3.1 分层测试

```text
单元测试
→ 协议与契约测试
→ 模块集成测试
→ 端到端功能测试
→ 算法场景测试
→ 性能与稳定性测试
→ 安装交付验收
```

### 3.2 固定测试集

算法版本对比必须使用冻结的测试集，不能仅使用训练图片或临时挑选的容易样本。

测试集应包含：

- 标准样本；
- 强光、弱光、反光和阴影；
- 模糊和运动拖影；
- 遮挡、重叠和密集目标；
- 目标位于 ROI 边界；
- 不同数量和不同类别；
- 正向、反向、停留和折返轨迹；
- 易误报背景；
- 无目标空场景；
- 已知缺陷和正常样本。

### 3.3 结果可复现

每次测试记录：

- 软件版本；
- 插件和模型版本；
- 协议版本；
- 配方版本；
- 相机、分辨率、曝光和光源；
- CPU、GPU、内存和驱动；
- 测试数据集版本；
- 原始结果和人工真值；
- 测试时间和执行人。

### 3.4 不以单次演示作为验收

算法至少按完整测试集计算指标；流水线计数至少执行多轮连续通过测试；稳定性必须执行规定时长的持续运行。

## 6. 测试指标与计算方法

### 6.1 静态计数

```text
绝对误差 = |预测数量 - 真值数量|
平均绝对误差 MAE = 所有样本绝对误差平均值
完全正确率 = 预测数量完全等于真值的样本数 / 总样本数
```

### 6.2 检测和缺陷

- Precision：报警中真实目标/缺陷比例；
- Recall：真实目标/缺陷被发现比例；
- 漏检率；
- 误报率；
- 不同目标尺寸、光照和遮挡分组指标。

### 6.3 动态与流水线计数

```text
累计误差率 = |系统累计 - 人工真值| / 人工真值
重复计数率 = 重复事件数 / 真实通过数
漏计率 = 漏计数 / 真实通过数
方向错误率 = 错误方向事件数 / 真实通过数
```

### 6.4 性能

- 平均推理延迟；
- P50/P95/P99 推理延迟；
- UI 实际帧率；
- 算法实际帧率；
- CPU/GPU/内存占用；
- 帧丢弃比例；
- 队列长度；
- 数据写入延迟。

### 6.5 首版建议门槛

以下为平台验收基线，具体算法项目应在配方中定义更严格指标：

| 指标 | 建议门槛 |
|---|---:|
| UI 预览 | ≥25 FPS（设备支持时） |
| 轻量 CPU 推理 | 满足任务设定 FPS，不统一写死 |
| 单图交互响应 | ≤1 秒为目标 |
| Worker 启动 | ≤10 秒，不含大型模型特殊约定 |
| 主程序连续运行 | ≥8 小时 |
| 事件数据库写入 | 不阻塞检测循环 |
| Worker 崩溃 | 主程序不得退出 |
| 计数恢复 | 已持久化累计值不得丢失 |

## 7. 测试阶段与进入/退出条件

### 7.1 单元测试阶段

进入：模块接口和核心领域对象已定义。  
退出：核心规则、协议、计数累计和配置校验通过，关键代码无未处理失败。

### 7.2 集成测试阶段

进入：WPF、Camera Provider、Worker 和 SQLite 可独立运行。  
退出：相机到算法再到 UI 和数据库的完整链路可重复运行。

### 7.3 系统测试阶段

进入：MVP 功能冻结。  
退出：主要功能、故障恢复和性能用例通过，无阻断级缺陷。

### 7.4 现场验收阶段

进入：使用真实相机、光源、产品和目标电脑完成配方配置。  
退出：现场节拍、准确率、连续运行和操作流程达到合同或项目指标。

## 8. 缺陷等级

| 等级 | 定义 | 示例 |
|---|---|---|
| Blocker | 无法启动或可能造成严重数据错误 | 主程序崩溃、累计数不可恢复 |
| Critical | 核心任务无法运行且无替代路径 | 相机无法取流、Worker无法通信 |
| Major | 主要功能错误但可绕过 | 跨线方向错误、NG图片未保存 |
| Minor | 次要功能或显示问题 | 次要文字、非核心筛选错误 |
| Trivial | 不影响使用的视觉细节 | 间距、颜色轻微偏差 |

发布要求：

- Blocker：0；
- Critical：0；
- Major：必须评审并有明确处置；
- 已知限制写入版本说明。

## 9. 功能测试用例

以下用例使用统一字段：

- **前置条件**：执行前必须满足；
- **步骤**：主要操作；
- **预期结果**：通过标准。

### 9.1 应用启动与导航

#### APP-001 正常启动

**前置条件：** 正常安装，基础配置和数据库可用。  
**步骤：** 启动 `VisionWorkbench.exe`。  
**预期结果：** 主窗口正常显示；无控制台窗口；导航可用；日志记录版本、数据目录和启动耗时。

#### APP-002 首次启动初始化

**前置条件：** 删除测试数据目录或使用全新用户环境。  
**步骤：** 首次启动软件。  
**预期结果：** 自动创建数据库、配置、日志和图片目录；不要求管理员权限；进入未配置状态。

#### APP-003 中文和空格路径

**前置条件：** 数据目录包含中文和空格。  
**步骤：** 设置数据目录、重启、执行一次检测。  
**预期结果：** 相机、Worker、图片保存和数据库均正常；路径不乱码。

#### APP-004 导航切换

**步骤：** 依次进入实时检测、任务、历史、算法、设备和设置页面。  
**预期结果：** 页面切换无异常；实时任务按设计保持或停止；不存在重复创建相机会话。

#### APP-005 非法运行状态保护

**前置条件：** 检测任务运行中。  
**步骤：** 尝试直接切换相机、模型或核心配方参数。  
**预期结果：** 系统禁止修改并提示先停止任务，或按设计执行安全切换；不得产生未定义状态。

### 9.2 角色与配置

#### CFG-001 操作员参数隐藏

**步骤：** 以操作员模式进入实时页面和设置。  
**预期结果：** 不显示置信度、IoU、模型路径、跟踪器和 GPU 底层参数。

#### CFG-002 工程师模式

**步骤：** 使用正确凭证进入工程师模式。  
**预期结果：** 可配置相机、ROI、检测线、方向、标准数量、灵敏度和保存策略。

#### CFG-003 错误凭证

**步骤：** 输入错误工程师凭证。  
**预期结果：** 权限不提升；记录安全审计但不记录明文密码。

#### CFG-004 配方保存与恢复

**步骤：** 创建配方、配置相机和规则、保存、退出并重启。  
**预期结果：** 配方完整恢复；插件、模型和相机绑定不丢失。

#### CFG-005 配方引用缺失插件

**前置条件：** 移除配方依赖的算法插件。  
**步骤：** 打开配方并尝试运行。  
**预期结果：** 软件可启动和查看历史；该配方明确显示不可运行及缺失组件，不得静默换模型。

#### CFG-006 参数越界

**步骤：** 在专家模式输入超出 Schema 范围的参数。  
**预期结果：** UI 和后端均拒绝保存；显示字段级错误；旧配置不被破坏。

### 9.3 多工位管理与结果归属

#### STA-001 新增多个工位

**步骤：** 在同一项目依次新增三个工位，编号设置为 `ST-001`、`ST-002`、`ST-003`，分别绑定不同配方和输入源，保存并重启软件。  
**预期结果：** 三个工位均完整恢复；列表按编号清晰显示；各自的设备和配方绑定不混淆。

#### STA-002 自动建议工位编号

**前置条件：** 项目中已有 `ST-001` 和 `ST-003`。  
**步骤：** 新建工位并使用系统建议编号。  
**预期结果：** 建议一个未占用编号（允许补空号 `ST-002` 或递增为 `ST-004`）；保存后满足唯一约束。

#### STA-003 重复和空编号校验

**步骤：** 分别尝试保存空白编号、仅含空格的编号、与已有编号大小写不同但等价的 `st-001`、超过 64 字符的编号。  
**预期结果：** UI 与服务端均拒绝保存；指出具体原因；原工位数据不被覆盖。

#### STA-004 编辑工位

**步骤：** 修改工位名称、配方和相机绑定后保存并重新启动。  
**预期结果：** 修改正确生效；未修改的 `StationCode` 保持不变；其他工位配置不受影响。

#### STA-005 删除无历史工位

**前置条件：** 目标工位未运行且没有检测记录。  
**步骤：** 删除工位并确认。  
**预期结果：** 工位从项目中移除；释放设备绑定；其他工位仍可正常运行。

#### STA-006 删除运行中工位

**前置条件：** 目标工位正在检测。  
**步骤：** 尝试删除该工位。  
**预期结果：** 系统拒绝删除并要求先停止；相机、Worker、批次和结果写入不进入半删除状态。

#### STA-007 归档有历史工位

**前置条件：** 工位已有批次、检测记录、图片和计数事件。  
**步骤：** 停止工位后执行删除/归档，再查询历史和导出 CSV。  
**预期结果：** 工位不再出现在可运行列表；历史仍可按原 `StationCode` 查询；图片、事件和导出来源不丢失。

#### STA-008 多工位并行运行

**步骤：** 同时启动至少三个工位，向各输入源送入可区分的固定数据集，连续运行 30 分钟。  
**预期结果：** 各工位拥有独立状态、会话、批次和计数；结果数量与各自真值一致；不存在跨工位串帧、串结果或串计数。

#### STA-009 单工位故障隔离

**前置条件：** 三个工位并行运行。  
**步骤：** 断开 `ST-002` 相机并使其 Worker 异常退出。  
**预期结果：** `ST-002` 独立告警并按策略恢复或停止；`ST-001`、`ST-003` 持续检测和落库，吞吐无不可接受下降。

#### STA-010 设备独占冲突

**步骤：** 将两个工位绑定同一个不支持共享的物理相机并尝试同时启动。  
**预期结果：** 后启动工位被阻止并显示占用它的工位编号；已运行工位不被中断。

#### STA-011 对外结果携带工位编号

**步骤：** 每个工位各产生 OK、NG 和待确认结果，捕获实时事件、PLC/消息适配器或 HTTP 输出。  
**预期结果：** 每条结果均含正确且非空的 `projectId`、`stationCode`、`taskId`、时间戳和判定；外部设备可仅凭 `projectId + stationCode` 区分来源。

#### STA-012 工位结果快照

**步骤：** 工位以 `ST-002` 完成检测，随后改名、改号或归档，再查看旧记录和重放对外结果。  
**预期结果：** 旧记录仍显示检测时的 `ST-002`；新检测使用新编号；不得用当前配置回填覆盖旧编号。

#### STA-013 项目级全部启动和停止

**前置条件：** 项目包含两个可运行工位和一个配置错误工位。  
**步骤：** 执行“全部启动”，查看明细后执行“全部停止”。  
**预期结果：** 两个有效工位启动成功，错误工位明确失败；项目汇总显示部分成功；全部停止能安全结束已启动工位和批次。

#### STA-014 单工位版本升级迁移

**前置条件：** 准备旧版本单工位数据库及检测历史。  
**步骤：** 使用新版本首次启动，检查迁移后项目、工位、记录和索引。  
**预期结果：** 自动创建默认项目与唯一工位编号；旧记录补写一致的编号快照；记录数、判定、图片路径不变；重复启动迁移保持幂等。

### 9.4 视觉配方向导

#### REC-001 新建静态计数配方

**步骤：** 选择静态计数模板、相机、ROI、类别和目标数量并试运行。  
**预期结果：** 配方保存成功；操作员模式可直接选择并运行。

**预期结果：** 创建新的 ModelRun/记录；旧结果不覆盖；可对比版本。

#### DAT-006 CSV 导出

**步骤：** 导出包含中文类别和批次的记录。  
**预期结果：** 字段、编码和数量正确；包含 `ProjectId`、`StationCode`；表格工具可正常打开。

#### DAT-007 数据库备份恢复

**步骤：** 创建备份、增加新数据、恢复旧备份。  
**预期结果：** 恢复前进行确认；恢复后数据与备份时间一致；图片缺失有明确标记。

#### DAT-008 数据库写入失败

**步骤：** 模拟数据库锁定或不可写。  
**预期结果：** 检测循环不永久卡死；记录失败进入告警；不得伪称已保存。

#### DAT-009 磁盘不足

**步骤：** 将测试磁盘空间降低至阈值以下。  
**预期结果：** 明显报警；停止或限制图片保存；结构化检测按策略继续。

#### DAT-010 图片被外部删除

**步骤：** 删除某历史记录关联图片后打开详情。  
**预期结果：** 显示图片缺失占位和路径信息；历史页面不崩溃。

## 19. CPU/GPU 与性能测试用例

#### PER-001 CPU 基准

**前置条件：** 强制 `CPUExecutionProvider`。  
**步骤：** 使用固定模型和视频运行 60 秒。  
**预期结果：** 输出平均、P95 延迟、FPS、CPU、内存和丢帧率；判断是否满足任务要求。

#### PER-002 CUDA 基准

**前置条件：** 可用 NVIDIA GPU。  
**步骤：** 同数据运行 CUDA 模式。  
**预期结果：** 正确使用目标 GPU；输出显存和延迟；结果精度在允许误差内与 CPU 一致。

#### PER-003 CUDA 不可用回退

**步骤：** 配置自动模式并禁用或移除 CUDA Provider。  
**预期结果：** 自动回退 CPU/其他可用后端；明确显示当前设备；不得直接崩溃。

#### PER-004 GPU 必需插件

**步骤：** 在无兼容 GPU 机器安装声明 GPU 必需的插件。  
**预期结果：** 安装或启动阶段明确阻止；不尝试错误的 CPU 运行。

#### PER-005 CPU 线程限制

**步骤：** 分别配置不同推理线程数。  
**预期结果：** 记录吞吐和 UI 响应；推荐值不占满系统导致界面卡顿。

#### PER-006 长时间性能

**步骤：** 连续运行 8 小时，定期采样进程指标。  
**预期结果：** 无持续内存增长、句柄泄漏和队列堆积；帧率无明显衰减。

#### PER-007 高负载数据写入

**步骤：** 配置保存大量证据图片并高频检测。  
**预期结果：** 数据保存异步；推理延迟和 UI 不发生不可接受阻塞；队列有上限。

#### PER-008 多分辨率

**步骤：** 在 720p、1080p 和目标 4K 场景运行。  
**预期结果：** 输出性能曲线；超过能力时给出不满足任务提示。

#### PER-009 模型冷启动与热推理

**步骤：** 分别记录首次加载、首次推理和稳定阶段推理。  
**预期结果：** 指标分开报告；模型不会每次请求重复加载。

## 20. 稳定性与恢复测试用例

#### STB-001 8 小时连续运行

**步骤：** 使用视频循环或真实相机连续检测 8 小时。  
**预期结果：** 无崩溃、死锁、明显内存增长和累计异常。

#### STB-002 频繁启停任务

**步骤：** 连续执行开始/停止 100 次。  
**预期结果：** 不残留相机会话、Worker、临时文件或数据库事务。

#### STB-003 频繁切换配方

**步骤：** 在停止状态下切换多个使用不同模型的配方。  
**预期结果：** Worker 生命周期正确；结果不会串到前一个配方。

#### STB-004 主程序正常退出

**步骤：** 检测中关闭窗口并确认退出。  
**预期结果：** 停止提交、flush/关闭 Worker、释放相机、提交数据库后退出。

#### STB-005 强制结束后恢复

**步骤：** 强制结束主程序并重新打开。  
**预期结果：** 数据库可打开；未完成任务标记为异常结束；累计值按事件恢复。

#### STB-006 系统睡眠恢复

**步骤：** 任务运行时让 Windows 睡眠并恢复。  
**预期结果：** 软件检测设备和时间中断；不直接沿用无效相机会话；提示重新确认。

#### STB-007 日志目录不可写

**步骤：** 模拟日志路径不可写。  
**预期结果：** 软件不因日志失败崩溃；提供备用提示或回退路径。

## 26. 现场验收方案

### 26.1 验收前准备

- 确认目标产品和异常定义；
- 固定相机、支架、光源和背景；
- 明确生产节拍；
- 建立现场真值样本；
- 确认计数边界、正反方向和折返规则；
- 明确是否允许并排、粘连和遮挡；
- 明确 OK、NG、待确认的业务处理；
- 冻结用于验收的软件、插件、模型和配方版本。

### 26.2 现场验收步骤

1. 硬件和相机检查；
2. 项目工位清单、工位编号和设备绑定检查；
3. 配方加载和画质检查；
4. 空场景测试；
5. 标准产品测试；
6. 已知困难样本测试；
7. 正向、反向和折返测试；
8. 多工位并行与单工位故障隔离测试；
9. 连续批量测试；
10. CPU/GPU 性能测试；
11. 相机断线和 Worker 重启测试；
12. 按工位核对批次、历史、证据、对外结果和导出；
13. 持续运行测试；
14. 双方确认验收结果和已知限制。

### 26.3 验收报告内容

```text
项目和现场信息
工位清单、工位编号和设备绑定
硬件与相机配置
软件、插件、模型和配方版本
测试数据和真值方法
准确率、漏计、重复、方向错误
平均/P95延迟和算法FPS
连续运行结果
故障恢复结果
多工位并行、隔离和结果归属结论
未通过项与整改计划
已知限制
验收结论
```

## 27. 测试数据与报告管理

每次正式测试生成唯一运行编号：

```text
TEST-20260816-001
```

建议归档：

```text
test-runs/
└── TEST-20260816-001/
    ├── environment.json
    ├── software-versions.json
    ├── recipe.json
    ├── metrics.json
    ├── raw-results.jsonl
    ├── failures/
    ├── logs/
    └── report.md
```

禁止只保留汇总百分比而丢弃失败样本。失败样本是后续模型改进和回归测试的关键资产。

## 28. 最终测试结论标准

一个版本可以进入试点交付，必须至少满足：

```text
核心纵向链路完整
相机和算法故障不拖垮主程序
CPU 基础模式可运行
GPU 可选加速及回退有效
静态/动态/流水线计数定义明确且通过冻结集
累计事件和人工修正可追溯
数据保存不阻塞实时检测
安装升级不破坏客户数据
连续运行达到规定时长
现场节拍和准确率达到具体项目门槛
```

平台测试通过不等于任意行业算法自动通过。每个算法包、模型版本和现场配方仍必须使用对应的真实数据集单独验收。
