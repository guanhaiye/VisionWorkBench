# 基于 YOLO11 的行为识别与智能监控算法方案

## 1. 建设目标

构建一套支持实时视频流的行为识别系统，实现：

- 人员、车辆及关键物品检测
- 人员跨帧跟踪与轨迹分析
- 人体姿态提取
- 越界、闯入、滞留、聚集等规则行为识别
- 跌倒、打架、奔跑等时序动作识别
- 抽烟、打电话、违规操作等人物—物品交互识别
- 异常事件报警、截图和录像回溯
- 支持多路摄像头及边缘端/服务器部署

首期采用“YOLO11 + 跟踪 + 姿态时序 + 视频动作模型 + 事件状态机”的混合方案。

## 2. 总体算法架构

```text
RTSP摄像头 / 本地视频
          ↓
视频解码与自适应抽帧
          ↓
画面质量检测、缩放、时间戳同步
          ↓
┌─────────────────────────────┐
│ YOLO11目标检测               │
│ YOLO11-Pose人体姿态          │
└─────────────────────────────┘
          ↓
ByteTrack多目标跟踪
          ↓
为每个人建立连续Track缓存
          ↓
┌──────────────┬───────────────┬────────────────┐
│ 区域轨迹分析  │ 姿态时序识别   │ RGB视频动作识别 │
│ 越界/滞留等   │ 跌倒/弯腰等    │ 打架/抽烟等     │
└──────────────┴───────────────┴────────────────┘
          ↓
人物—物品关系与多模型融合
          ↓
事件状态机、连续帧确认、报警防抖
          ↓
报警截图 + 前后事件录像 + API/WebSocket推送
```

算法系统分为五层：

1. 视频接入层
2. 目标感知层
3. 时序理解层
4. 事件决策层
5. 推理部署与业务接口层

## 3. 核心模型选择

### 3.1 目标检测

基线模型使用 YOLO11。

| 环境 | 推荐模型 | 输入尺寸 |
|---|---|---:|
| Jetson等边缘设备 | YOLO11n | 640 |
| 普通GPU服务器 | YOLO11s | 640或960 |
| 远距离、小目标较多 | YOLO11m | 960或1280 |
| 追求高精度、离线分析 | YOLO11l | 960或1280 |

初期需要检测的类别：

- person
- helmet
- phone
- cigarette/smoking-object
- vehicle
- tool
- fire/smoke
- 与业务有关的设备和防护用品

COCO预训练模型可直接检测人员、手机、车辆等常见对象；安全帽、香烟、特殊工具和设备通常需要采集现场数据重新训练。

### 3.2 人体姿态

采用 `YOLO11s-pose` 作为基线，输出人体17个关键点。姿态模型用于跌倒、躺地、弯腰、蹲下、举手、快速挥臂、身体冲突和工序动作分析。

低算力设备可换成 `YOLO11n-pose`，遮挡严重或人体较小时使用更大模型或提高输入分辨率。

### 3.3 多目标跟踪

首选 ByteTrack。每个目标维护：

```json
{
  "track_id": 108,
  "camera_id": "camera_01",
  "bbox": [320, 140, 480, 590],
  "confidence": 0.91,
  "first_seen": 1770000000,
  "last_seen": 1770000005,
  "trajectory": [],
  "keypoint_sequence": [],
  "clip_buffer": []
}
```

跟踪器负责稳定ID、移动轨迹、速度方向、区域停留时间、姿态缓存和事件去重。推荐保留约10～30秒的环形视频缓存。

## 4. 行为识别算法设计

### 4.1 越界与区域闯入

输入为人员检测框、Track ID、配置的多边形区域和时间信息。使用人员框底边中心作为位置点：

```text
foot_point = ((x1 + x2) / 2, y2)
```

基本规则：

```text
foot_point进入警戒区
AND 连续存在时间 ≥ 0.5秒
AND 检测平均置信度 ≥ 0.5
→ 触发闯入事件
```

支持禁入、离开、单向越线、指定时间段和白名单过滤。采用连续3～5帧确认，避免检测框抖动导致误报。

### 4.2 滞留与徘徊

滞留条件：

```text
人员处于指定区域
AND 停留时间 > T
AND 有效跟踪率达到阈值
```

可设置区域停留超过30秒为预警，超过60秒正式报警。

徘徊通过滑动时间窗分析总移动距离、净位移、方向变化、重复进入和停留时长：

```text
loiter_score =
0.30 × 停留时长得分
+ 0.25 × 方向变化得分
+ 0.25 × 重复经过得分
+ 0.20 × 路径长度/净位移比
```

### 4.3 人员聚集

```text
人数 ≥ N
AND 持续时间 ≥ T
→ 聚集事件
```

可加入空间密度：

```text
density = ROI内人数 / ROI实际面积
```

默认示例：人数≥5并持续5秒时预警；人数≥8并持续10秒时报警；人数低于阈值并持续5秒后解除。遮挡严重时可以结合人头检测校正人数。

### 4.4 跌倒识别

跌倒采用三阶段算法，不能仅依赖人体框宽高比。

#### 第一阶段：快速候选检测

计算身体主轴角度、肩髋高度、人体框宽高比、髋部下降速度、头脚相对位置和关键点离地程度。

```text
身体主轴接近水平
OR 人体框宽高比明显增大
AND 髋部在短时间快速下降
```

#### 第二阶段：姿态时序分类

连续关键点序列输入姿态时序模型：

```text
输入：T × 17 × 3
T = 30～60帧
3 = x、y、confidence
```

预处理包括髋部中心归一化、尺度归一化、缺失点插值、置信度保留和速度/加速度计算。

模型建议：

- 第一版：ST-GCN
- 精度升级：PoseC3D
- 轻量部署：TCN或小型Transformer

分类标签至少包含 `normal`、`walking`、`sitting`、`bending`、`squatting`、`lying`、`falling`、`getting_up`。

#### 第三阶段：倒地持续确认

```text
跌倒概率 > 0.75
AND 快速下降已发生
AND 低位姿态持续 ≥ 1.5秒
→ 跌倒报警
```

融合分数：

```text
fall_score =
0.55 × 姿态时序模型
+ 0.20 × 身体倾角
+ 0.15 × 垂直下降速度
+ 0.10 × 倒地持续时间
```

### 4.5 打架与推搡识别

采用“候选筛选 + RGB时序模型 + 姿态交互特征”。当两人距离快速缩短、检测框接近、手腕速度异常、移动加速度高或轨迹快速变化时，启动视频模型。

RGB模型优先级：

1. X3D-S：轻量实时
2. SlowFast：速度和精度平衡
3. VideoMAE：服务器高精度复核

输入以相关人员为中心裁剪2～4秒、16～32帧、224×224的视频片段。训练标签应包含打架、推搡以及拥抱、握手、跑动、玩耍、搬运、正常互动等易混淆负样本。

```text
fight_score =
0.55 × RGB动作模型
+ 0.20 × 双人姿态交互
+ 0.15 × 手腕运动强度
+ 0.10 × 轨迹碰撞强度
```

### 4.6 抽烟与打电话

抽烟融合香烟/烟雾检测、手腕靠近嘴部、周期性手嘴动作和局部视频分类：

```text
smoking_score =
0.35 × 香烟/烟雾检测
+ 0.30 × 手嘴空间关系
+ 0.25 × 局部视频分类
+ 0.10 × 重复动作
```

如果人物在画面中的高度低于约100～150像素，香烟小目标通常难以可靠识别，应降低置信度或调整摄像头。

打电话结合手机检测、手机与耳部距离、手腕与耳部距离及持续时间，区分耳边通话、看屏幕和手持手机。

### 4.7 奔跑与追逐

完成摄像头透视标定后，可将像素速度转换为实际速度；未标定时使用人体框高度归一化：

```text
normalized_speed = 像素移动距离 / 人体框高度 / 时间
```

追逐行为需要多人高速移动、方向近似一致、前后距离较小且速度变化相关。

### 4.8 违规操作与标准工序

采用“目标检测 + 人物物品关系 + 有限状态机”。例如：

```text
进入工位
→ 穿戴防护用品
→ 拿取工具
→ 操作设备
→ 放回工具
→ 离开工位
```

如果人员未经过防护用品确认状态就进入操作状态，触发违规报警。

## 5. 多模型调度策略

### 一级：常驻轻量推理

- YOLO11人员/物品检测
- ByteTrack
- ROI规则
- 简单轨迹特征

### 二级：条件触发推理

- YOLO11-Pose
- 姿态序列模型
- 人物局部视频分类

### 三级：报警复核

- SlowFast或VideoMAE
- 多窗口投票
- 可选视频大模型事件描述

重型模型仅在出现候选事件时运行，以降低多路视频的GPU消耗。

## 6. 事件状态机

每个“摄像头—Track ID—事件类型”维护独立状态：

```text
NORMAL → SUSPECTED → CONFIRMING → ALARMED → COOLDOWN → RECOVERED
```

- 连续3帧超过候选阈值：进入疑似状态
- 持续1秒超过确认阈值：进入确认状态
- 模型和规则融合通过：产生报警
- 报警后进入冷却期，避免重复报警
- 行为恢复正常后解除

采用双阈值，例如进入阈值0.75、退出阈值0.45，避免事件在阈值附近反复开关。

## 7. 数据采集与标注

### 7.1 数据来源

1. 公开数据集用于预训练和初始化
2. 模拟拍摄用于快速构造目标行为
3. 真实现场录像用于适配摄像头环境

覆盖白天、夜间、逆光、不同距离、不同角度、遮挡、多人和相似正常行为。

### 7.2 标注内容

| 任务 | 标注内容 |
|---|---|
| 目标检测 | 类别和检测框 |
| 姿态识别 | 视频片段级动作标签 |
| 打架等动作 | 开始时间、结束时间、人物ID |
| 区域行为 | 管理端配置ROI |
| 工序识别 | 步骤开始、结束及相关物品 |
| 跟踪评估 | 跨帧人员ID |

MVP阶段建议每种动作准备500～1000段正样本和1000～3000段相似负样本，每段2～8秒，至少覆盖3～5个摄像头。检测任务每个自定义类别至少准备1000个有效实例。

### 7.3 数据集划分

按摄像头、日期或场景划分，避免同一原始录像切片后同时进入训练集和测试集：

```text
训练集：70%
验证集：15%
测试集：15%
```

## 8. 模型训练

### 8.1 YOLO11检测模型

使用预训练权重初始化，先冻结部分骨干训练，再解冻全网络微调。增强包括亮度、对比度、色温、运动模糊、压缩噪声、随机遮挡、远距离缩小和低照度模拟。动作数据不能使用破坏行为语义的旋转增强。

### 8.2 姿态时序模型

输入特征：

```text
[x, y, confidence, vx, vy, ax, ay]
```

使用交叉熵或Focal Loss，配合类别加权采样、困难负样本挖掘和事件级采样解决类别不平衡。

### 8.3 RGB动作模型

从Kinetics等预训练权重微调。先冻结骨干训练分类头，再以较小学习率全量微调，使用多时间段采样和摄像头级交叉验证。

## 9. 模型融合

统一事件候选格式：

```json
{
  "camera_id": "camera_01",
  "track_ids": [108, 121],
  "event_type": "fight",
  "start_time": 1770000000.3,
  "model_scores": {
    "rgb_action": 0.84,
    "pose_action": 0.72,
    "trajectory": 0.65,
    "object_relation": 0.10
  }
}
```

MVP阶段采用人工配置权重：

```text
final_score = Σ(weight_i × score_i)
```

数据积累后，可使用Logistic Regression、XGBoost或小型MLP训练融合模型。

## 11. 性能与部署

### 11.1 技术栈

开发阶段：

- Python、PyTorch
- OpenCV、FFmpeg
- FastAPI
- MMAction2

生产阶段：

- ONNX Runtime或TensorRT
- FFmpeg硬件解码
- Redis维护Track及事件状态
- PostgreSQL保存配置和元数据
- 对象存储保存截图和录像
- WebSocket或消息队列推送事件

### 11.2 推荐推理频率

| 模块 | 推荐频率 |
|---|---:|
| 视频解码 | 15～25 FPS |
| 人员检测 | 8～15 FPS |
| 跟踪更新 | 15～25 FPS |
| 姿态模型 | 5～10 FPS |
| 区域规则 | 5～10次/秒 |
| RGB动作模型 | 每0.5～1秒滑动一次 |
| 高精度复核 | 候选事件触发 |

### 11.3 硬件建议

- 概念验证：RTX 3060/4060及以上，内存16GB以上
- 小型服务器：RTX 4070 Ti Super/4080/4090级别，内存32～64GB
- 边缘端：Jetson Orin系列，使用YOLO11n/s和TensorRT FP16/INT8

实际支持路数必须根据分辨率、模型、推理频率和视频编码进行压测。

## 12. 评估指标

检测模型关注Precision、Recall、mAP50、mAP50-95和小目标召回率；跟踪关注IDF1、HOTA、ID Switch和轨迹中断率；行为模型关注事件级Precision、Recall、F1、PR-AUC、混淆矩阵和平均检出延迟。

生产指标包括：

- 每路摄像头每天误报次数
- 每类事件漏报率
- 95分位报警延迟
- 单路GPU占用
- 视频流断线恢复时间
- 夜间及遮挡场景召回率

MVP参考目标：

| 指标 | 目标 |
|---|---:|
| 越界召回率 | ≥95% |
| 滞留召回率 | ≥95% |
| 跌倒召回率 | ≥90% |
| 打架召回率 | ≥85% |
| 简单事件报警延迟 | ≤1秒 |
| 时序行为报警延迟 | 1～3秒 |
| 视频流断线恢复 | ≤10秒 |

## 14. 最终推荐组合

```text
目标检测：YOLO11s
人体姿态：YOLO11s-pose
目标跟踪：ByteTrack
轨迹行为：ROI几何规则 + 滑动窗口 + 状态机
跌倒行为：YOLO11-Pose + ST-GCN/PoseC3D + 倒地持续确认
打架行为：轨迹/姿态候选筛选 + X3D-S
高精度复核：SlowFast或VideoMAE，按需启用
事件决策：人工权重融合 + 双阈值状态机
部署：ONNX Runtime起步，生产环境TensorRT FP16
```

如果首期资源有限，优先实现越界、滞留、人员聚集和跌倒。前三类复用检测跟踪底座，跌倒用于建立完整的姿态时序训练能力。打架、抽烟等高难度行为放到第二批。

YOLO11是系统的基础视觉模型，不是最终行为分类器。最终精度主要由现场数据质量、相似负样本、连续时间判断和事件状态机共同决定。商业部署前还需要确认采用的YOLO实现及相关依赖的授权要求。
